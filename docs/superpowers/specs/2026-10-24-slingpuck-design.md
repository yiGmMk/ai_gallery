# 弹射冰球（Sling Puck）设计文档

日期：2026-10-24
状态：已确认范围，待实现

## 意图与为什么

在 ai_gallery 的 games 栏目新增一款完整可玩的 2.5D 弹射冰球网页游戏。视觉参考用户提供的木制棋盘截图：固定斜俯视角、厚木框、有厚度的圆形棋子、柔和阴影、可形变的弹力带。玩家使用鼠标或触屏拖拽自己半场的棋子，拉向己方弹力带蓄力，松手后穿过中间隔板的小洞，目标是把所有棋子打到对方半场。

本轮只交付**人机对战**。在线匹配与好友房需要常驻 Node 服务，而本站是 Netlify/Vercel 静态/SSG 站点；用户已明确本轮不引入服务器。因此核心规则与物理实现为与 UI 解耦的纯模块，未来 Colyseus 服务端可直接复用，但本轮不包含联机代码、匹配队列或 WebSocket。

## 目标

1. 新增 `/{zh,en}/games/slingpuck` 页面，并在 games 列表展示卡片。
2. 3D 木制棋盘、圆形棋子、隔板、弹力带、阴影和形变，固定斜俯视，主角色的半场始终位于屏幕下方。
3. 完整规则：每边 5 枚棋子；轮流；每回合弹射一枚己半场棋子；棋子基本静止后换边；先清空己方半场者胜；回合倒计时超时跳过。
4. 鼠标与触屏拖拽蓄力，操作限制在己方半场、拉伸距离和最大力度内；松手方向与拖拽方向相反。
5. Rapier 2D 物理：真实碰撞、反弹、摩擦减速、CCD 防高速穿墙；碰撞音效、力度提示、当前回合提示。
6. 简单/普通/困难三级 AI，与玩家使用同一套规则和物理模拟，以瞄准误差与搜索量区分难度。
7. 完整 SEO/i18n/说明文档；核心逻辑和 AI 有 Jest 测试；真实浏览器验证一整局人机对战。

## 非目标 / 反目标

- 不做联机匹配、好友房、服务器、账号或排行榜（本轮）。
- 不做 TypeScript 迁移。项目是纯 JS，新增代码沿用 JS + JSDoc，保持与仓库一致。
- 不引入 React Three Fiber；直接用 Three.js，便于逐帧控制和销毁。
- 不追求物理拟真到“真实弹力带材料模型”；弹力带是视觉与蓄力隐喻，不参与碰撞。
- 避免把游戏做成独立静态页或 iframe；必须作为现有 Next.js App Router 页面集成。
- 避免复制参考图中无关的品牌/玩家名；棋盘只保留通用游戏标识。

## 约束

- Next.js 14 App Router + React 18 + Tailwind + 现有 Jest 配置。
- 已存在依赖：`three@^0.169.0`。新增 `@dimforge/rapier2d-compat@^0.21.0`。

- 页面必须适配桌面鼠标和手机触屏；棋盘竖屏比例，页面主体突出棋盘。
- 文案 zh/en 双份；新增字典键与 `seo.slingpuck`。
- 不修改既有游戏行为；仅修改共用配置/字典以注册新游戏。

## 玩法决定（用户已确认 + 实现决定）

### 棋盘与坐标

- 物理平面为 2D：`x` 横向，`y` 纵向。玩家半场 `y < 0`，电脑半场 `y > 0`。
- 棋盘内区 720 × 1200；棋子半径 34（直径 68）；隔板厚 24，中央开口 76（比棋子宽 8）。
- 隔板两端做圆角，开口内缘平滑。
- 两端弹力带位于各自端部附近（`y = ∓400`），仅作为蓄力视觉与操作锚点，不参与碰撞；棋子仍受外围木框碰撞。
- 初始每边 5 枚，颜色黑白交错但**颜色不代表归属**；任意落在己方半场的棋子都可在己方回合操作。

### 弹射

- 拖拽己方半场棋子向己方弹力带方向移动；拖动只允许在“向后”的半平面内，并被限制为与正后方夹角不超过约 58°，保证发射方向朝对方半场。
- 拖拽点被限制在己方半场和棋盘内；最大拉伸 170。
- 松手发射方向 = 从拖拽点指向棋子原位置（即拖拽的反方向）；力度 = 拉伸长度 / 最大拉伸。
- 发射速度 = 520 + power × 1830（上限 2350 单位/秒）。
- 拖拽过程中棋子网格跟随指针以展示蓄力；物理体保持在原位，松手后从原位施加冲量，避免拖拽重叠导致物理爆炸。播放时先做短促回弹再播放模拟帧。
- 未超过最小拉伸（16）则不发射，棋子回到原位。

### 回合与胜负

- 玩家先手。每回合只能发射一枚。
- 发射后开始固定步长模拟，直到所有棋子“基本静止”0.45 秒，或最多 8 秒（强制清零速度）。
- 结算时先看是否有人清空己方半场：
  - 双方半场都空：本回合发射者胜。
  - 仅发射者半场空：发射者胜。
  - 仅对方半场空：对方胜（位置规则，先空者胜）。
  - 否则切换到对方回合。
- 回合倒计时 30 秒；超时跳过本回合，不发射。
- 被撞回己方半场的棋子下一回合仍可被己方操作。
- 胜者产生后锁定输入，展示结算面板，可再来一局或换难度。

### AI

- AI 作为 `MatchEngine` 之上的策略：只选择己方半场棋子、构造合法拖拽点、调用同一套模拟。
- 候选：每枚己方棋子 × 多个目标点 × 多档力度；逐个用独立物理世界模拟至多约 4.5 秒。
- 评分：让己方半场棋子数减少权重最高；增加对方半场棋子数次之；清空己方半场给巨大奖励；导致对方半场清空给巨大惩罚；发射者获胜额外奖励；时长轻微惩罚。
- 难度：
  - 简单：候选约 6 个，角度误差 σ≈0.20 rad，力度误差 σ≈16%，从前列候选中随机。
  - 普通：候选约 16 个，σ≈0.075 rad，力度误差 σ≈7%，取前 3。
  - 困难：候选约 30 个，σ≈0.022 rad，力度误差 σ≈2.5%，取最优。
- 随机数使用可注入的种子 RNG，便于测试复现。
- **性能预算**：候选模拟 `maxTime` 降为 3.0 秒、`recordFrames: false`；每次 AI 决策总耗时预算 250 ms，超预算立即返回当前最优候选。搜索同步执行并显示“思考中”，避免移动端长时间无反馈。未来联机时该策略可原样搬到服务端或 Worker。

### 封面与交互边界

- games 卡片封面使用本地 `public/games/slingpuck/cover.jpeg`，由实际游戏截图生成；若截图流程失败，用用户提供的参考图副本兜底。**不依赖外部图片上传**。
- 开始面板与结算面板是覆盖在棋盘上的遮罩；开始前与结算后棋盘输入禁用，这是有意的交互边界。对局中不使用遮罩。

### 验证方式

- 使用 Playwright（仓库内无现成浏览器依赖，需要时作为 devDependency 安装）执行脚本化完整对局：通过仅开发环境暴露的 `window.__slingPuck` 获取棋子的屏幕坐标与建议射击点，再用真实鼠标/指针事件拖拽；AI 回合计时自动进行。
- 桌面视口完整对局一次；手机视口（390×844）完整对局一次并检查无水平溢出。第一发按实时速度验证动画，其余发次可加速回放以控制验证时长。
- 截图用于人工检查棋盘、阴影、弹力带形变与 HUD 重叠。

### 核心数据流

1. `content.js` 挂载 `SlingPuckScene`，动态 `loadRapier()`。
2. 点击开始：`new MatchEngine(rapier, { side: 'player' })`，场景同步初始棋子。
3. 玩家拖拽：`clampDragPoint()` 得到合法点 → 场景显示拉伸与瞄准 → 松手。
4. `engine.shoot({ side, puckId, dragPoint })` 同步完成整段物理模拟，返回 `frames`、`events`、最终棋子、胜者、下一回合。
5. 场景按 60fps 回放 `frames`；到对应帧触发碰撞特效/音效；播完同步最终状态并启动下一回合。
6. 电脑回合：等待约 600ms → `chooseShot()` → 同样走 `engine.shoot()` 与回放。
7. 计时器在“可操作回合”开始计时；超时调用 `engine.passTurn()`。

### 物理决定

- Rapier 2D，零重力，固定步长 1/60 s，`world.timestep` 固定。
- 棋子动态圆盘：线性阻尼 1.35，角阻尼 2.6，摩擦 0.22，弹性 0.58，CCD 开启，密度 1。
- 外围木框、隔板矩形与端部圆角使用固定碰撞体，厚 30+，降低穿透风险。
- 碰撞事件通过 `EventQueue` 收集，记录强度、位置、帧号；强度由碰撞前速度估计。
- 模拟在独立世界中运行；AI 每次候选新建世界并在结束时 `free()`。
- 模拟必须可重复：相同初始状态、相同射击、相同步数得到相同结果（测试锁定）。

### 渲染决定

- Three.js，正交相机固定斜俯视（约 50° 仰角），映射：物理 `(x, y)` → 场景 `(x, -y)` 平面，棋子在棋盘表面上方。
- 木纹、棋盘印刷、棋子顶面纹理用 Canvas 运行时生成，避免额外图片资源。
- 棋盘：厚底板 + 四周木框 + 内嵌印刷面 + 隔板 + 金色弹力带锚点 + 黑色弹力带。
- 棋子：圆柱体（侧/顶/底三材质），顶面同心环纹理与偏心小点表现旋转。
- 光照：半球光 + 主方向光（PCFSoft 阴影）+ 补光 + Canvas 环境贴图（PMREM）。
- 弹力带：TubeGeometry + CatmullRomCurve3；拖拽时曲线经过拖拽点形成形变。
- 当前可操作棋子下方显示柔和金色光晕；拖拽时显示 3D 瞄准箭头。
- 碰撞特效：地面扩散圆环 + 轻微相机震动；音效由 WebAudio 合成。
- 桌面/移动端通过 ResizeObserver 自适应；容器竖屏为主，限制最大高度，避免页面被 HUD 撑高。

## 左给实现者的决定

- 具体木纹/棋盘印刷的视觉细节、配色与阴影强度可调，以接近参考图的暖木桌游质感为准。
- 物理阻尼/速度可在测试与浏览器验证中微调，但必须满足：满力可穿过中央开口、正常力度下多数棋子能到达对方半场、棋子能在数秒内静止。
- AI 搜索的具体目标点网格与权重可微调，但必须遵守同一规则并有可复现随机数。
- 页面文档的具体措辞可调整，但需覆盖操作、规则、难度、常见问题。
